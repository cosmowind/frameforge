# 代码规范

## 开发流程

### 1. Git 备份
每次开发前和完成后都要进行 Git 备份：

```bash
# 开发前：拉取最新代码
git pull

# 开发中：定期提交
git add .
git commit -m "描述性的提交信息"

# 开发后：推送到远程
git push
```

### 2. 文档维护
在 `docs/` 目录维护核心文档，其他地方引用而不重复：

- `项目目录结构.md` - 项目结构
- `功能清单.md` - 已完成功能
- `错误记录.md` - Bug 和解决方案
- `用户需求记录.md` - 用户需求
- `代码规范.md` - 本文件

### 3. 自动更新文档
每次完成功能后，更新相关文档：

- 更新 `功能清单.md` 添加新功能
- 如有 Bug，记录到 `错误记录.md`
- 更新 `README.md` 引用最新文档

### 4. 自动备份
完成开发后执行：

```bash
npm run backup  # 自动提交并推送
```

## 代码规范

### TypeScript
- 使用 TypeScript 严格模式
- 所有函数都要有类型注解
- 避免使用 `any` 类型

### React
- 使用函数组件和 Hooks
- 组件文件使用 PascalCase 命名
- 一个文件一个组件

### 命名规范
- 文件名：`PascalCase.tsx` (组件) 或 `camelCase.ts` (工具)
- 变量：`camelCase`
- 常量：`UPPER_SNAKE_CASE`
- 类型：`PascalCase`

### 注释
- 复杂逻辑必须添加注释
- 公共 API 使用 JSDoc 注释
- 中文注释优先

## 项目结构规范

### 核心目录
- `src/` - 源代码
- `docs/` - 核心文档
- `other/` - 其他文件

### 文件组织
- 组件放在 `src/renderer/components/`
- 服务放在 `src/renderer/services/`
- 类型放在 `src/renderer/types/`

## 提交规范

### 提交信息格式
```
<type>: <subject>

<body>
```

### Type 类型
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 代码格式
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具

### 示例
```
feat: 添加视频缩放功能

- 在右侧面板添加缩放滑块
- 支持 50%-150% 缩放
- 视频缩小后下方组件自动上移
```

## 测试规范

### 测试文件
- 测试文件放在 `other/tests/`
- 命名：`*.test.ts` 或 `*.spec.ts`

### 测试类型
- 单元测试：测试单个函数
- 集成测试：测试组件交互
- E2E 测试：测试完整流程

## 文档规范

### 文档引用
在其他文件中引用核心文档：

```markdown
详细信息请查看：[功能清单](docs/功能清单.md)
```

### 避免重复
- 核心内容只在 `docs/` 中维护
- 其他地方通过引用链接
- 保持文档同步更新

## 发布流程

### 1. 测试
```bash
npm run build
npm start
```

### 2. 打包
```bash
npm run dist
```

### 3. 测试安装包
- 安装并测试所有功能
- 检查性能和稳定性

### 4. 发布
- 更新版本号
- 创建 Git tag
- 发布到分发渠道

## 维护规范

### 定期维护
- 每周检查依赖更新
- 每月清理无用代码
- 每季度重构优化

### 文档更新
- 功能完成后立即更新文档
- 发现 Bug 立即记录
- 用户反馈及时记录
